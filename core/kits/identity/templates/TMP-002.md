---

# 1. Purpose

The Character Template provides the canonical reusable template for representing a character within Kaivo Core.

It standardizes the creation of Character identities while remaining fully consistent with the Identity Specification and implementation-neutral.

---

# 2. Scope

The Character Template defines:

* The reusable structure for Character identities.
* Conformance requirements.
* Template boundaries.

The Character Template does not define:

* Narrative behavior
* Story logic
* Authentication
* Authorization
* Runtime behavior
* Storage mechanisms
* User interface behavior

---

# 3. Template Overview

The Character Template provides a reusable foundation for creating Identity instances representing characters.

Every instance created from this template shall conform to the Identity Specification.

---

# 4. Required Structure

Every Character instance created from this template shall include:

* Exactly one canonical Identity.
* A descriptive representation associated with that Identity.
* Conformance to the Core Ontology.
* Conformance to the Core Asset Model.
* Conformance to the Identity Model.
* Conformance to the Identity Specification.

---

# 5. Template Principles

Every Character instance shall be:

* Uniquely identifiable.
* Stable throughout its lifecycle.
* Reusable.
* Traceable.
* Referenceable.
* Implementation-neutral.

---

# 6. Conformance Requirements

A Character instance created from this template shall:

* Represent exactly one character.
* Preserve Identity throughout its lifecycle.
* Separate Identity from descriptive information.
* Maintain compatibility with all governing Core artifacts.

---

# 7. Boundaries

The Character Template does not define:

* Character relationships
* Organizational roles
* Permissions
* Runtime state
* Workflow behavior
* Application-specific attributes

---

# 8. Canonical Constraints

### C1

A Character instance shall represent exactly one character.

---

### C2

A Character instance shall possess exactly one canonical Identity.

---

### C3

Identity shall remain stable throughout the lifecycle of the represented character.

---

### C4

Descriptive information shall not redefine Identity.

---

### C5

The Character instance shall conform to the Identity Specification.

---

### C6

The Character instance shall remain implementation-neutral.

---

# 9. Conformance

An implementation conforms to this template if it:

* Produces Character identities that satisfy this template.
* Conforms to the Identity Specification.
* Preserves canonical Identity.
* Maintains compatibility with the Core Ontology.
* Maintains compatibility with the Core Asset Model.
