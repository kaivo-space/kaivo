# 1. Purpose

The Role Template provides the canonical reusable template for representing a role within Kaivo Core.

It standardizes the creation of Role identities while remaining fully consistent with the Identity Specification and implementation-neutral.

---

# 2. Scope

The Role Template defines:

* The reusable structure for Role identities.
* Conformance requirements.
* Template boundaries.

The Role Template does not define:

* Organizational governance
* Permission models
* Access control
* Business responsibilities
* Runtime behavior
* Storage mechanisms
* User interface behavior

---

# 3. Template Overview

The Role Template provides a reusable foundation for creating Identity instances representing roles.

Every instance created from this template shall conform to the Identity Specification.

---

# 4. Required Structure

Every Role instance created from this template shall include:

* Exactly one canonical Identity.
* A descriptive representation associated with that Identity.
* Conformance to the Core Ontology.
* Conformance to the Core Asset Model.
* Conformance to the Identity Model.
* Conformance to the Identity Specification.

---

# 5. Template Principles

Every Role instance shall be:

* Uniquely identifiable.
* Stable throughout its lifecycle.
* Reusable.
* Traceable.
* Referenceable.
* Implementation-neutral.

---

# 6. Conformance Requirements

A Role instance created from this template shall:

* Represent exactly one role.
* Preserve Identity throughout its lifecycle.
* Separate Identity from descriptive information.
* Maintain compatibility with all governing Core artifacts.

---

# 7. Boundaries

The Role Template does not define:

* Organizational hierarchy
* Security policies
* Runtime state
* Workflow behavior
* Application-specific attributes
* Permission implementation

---

# 8. Canonical Constraints

### C1

A Role instance shall represent exactly one role.

---

### C2

A Role instance shall possess exactly one canonical Identity.

---

### C3

Identity shall remain stable throughout the lifecycle of the represented role.

---

### C4

Descriptive information shall not redefine Identity.

---

### C5

The Role instance shall conform to the Identity Specification.

---

### C6

The Role instance shall remain implementation-neutral.

---

# 9. Conformance

An implementation conforms to this template if it:

* Produces Role identities that satisfy this template.
* Conforms to the Identity Specification.
* Preserves canonical Identity.
* Maintains compatibility with the Core Ontology.
* Maintains compatibility with the Core Asset Model.
