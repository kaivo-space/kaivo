---

# 1. Purpose

The Person Template provides the canonical reusable template for representing a person within Kaivo Core.

It standardizes the creation of Person identities while remaining fully consistent with the Identity Specification and implementation-neutral.

---

# 2. Scope

The Person Template defines:

* The reusable structure for Person identities.
* Conformance requirements.
* Template boundaries.

The Person Template does not define:

* Authentication
* Authorization
* Organizational policies
* Runtime behavior
* Storage mechanisms
* User interface behavior

---

# 3. Template Overview

The Person Template provides a reusable foundation for creating Identity instances representing persons.

Every instance created from this template shall conform to the Identity Specification.

---

# 4. Required Structure

Every Person instance created from this template shall include:

* Exactly one canonical Identity.
* A descriptive representation associated with that Identity.
* Conformance to the Core Ontology.
* Conformance to the Core Asset Model.
* Conformance to the Identity Model.
* Conformance to the Identity Specification.

---

# 5. Template Principles

Every Person instance shall be:

* Uniquely identifiable.
* Stable throughout its lifecycle.
* Reusable.
* Traceable.
* Referenceable.
* Implementation-neutral.

---

# 6. Conformance Requirements

A Person instance created from this template shall:

* Represent exactly one person.
* Preserve Identity throughout its lifecycle.
* Separate Identity from descriptive information.
* Maintain compatibility with all governing Core artifacts.

---

# 7. Boundaries

The Person Template does not define:

* Organizational roles
* Permissions
* Security models
* Runtime state
* Workflow behavior
* Application-specific attributes

---

# 8. Canonical Constraints

### C1

A Person instance shall represent exactly one person.

---

### C2

A Person instance shall possess exactly one canonical Identity.

---

### C3

Identity shall remain stable throughout the lifecycle of the represented person.

---

### C4

Descriptive information shall not redefine Identity.

---

### C5

The Person instance shall conform to the Identity Specification.

---

### C6

The Person instance shall remain implementation-neutral.

---

# 9. Conformance

An implementation conforms to this template if it:

* Produces Person identities that satisfy this template.
* Conforms to the Identity Specification.
* Preserves canonical Identity.
* Maintains compatibility with the Core Ontology.
* Maintains compatibility with the Core Asset Model.
